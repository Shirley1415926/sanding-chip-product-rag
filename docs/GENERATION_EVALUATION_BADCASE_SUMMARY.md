# 真实生成评估预修复 Badcase 摘要

状态：已归档的本地 DeepSeek 预修复运行摘要；本文件不包含原始模型回答、完整检索正文、API 配置或其他敏感信息。

原始 trace 与报告已复制到 gitignore 的 `data/runtime/generation_evaluation/pre-fix-badcase-evidence/`，仅供本机复盘，不会提交。该次运行证明评估机制实际调用过模型，但不能作为修复后的质量结论；修复后尚未重新调用真实 LLM。

## 发现的问题

| 用例 | 观察到的问题 | 根因假设 | 本次修复 |
| --- | --- | --- | --- |
| G11 | 两件商品的公开展示价均有检索依据，但模型错误转人工。 | 提示未明确规定“多商品比较且各自有证据”应逐项回答；原回答不要求声明实际使用的证据。 | 对多商品比较加入明确指令；上下文为命名商品保留多个证据片段；模型须引用对应 `S` ID。 |
| G13 | 选品事实大体正确，但出现内部 `product_id`，并展示了无关候选来源。 | 模型上下文包含内部 metadata；编排层将完整 Top-K 一并作为用户来源。 | 从 prompt 和公开输出剥离 `product_id`；仅返回模型有效引用映射的来源。 |
| G14 | 推荐结论对应商品，但用户来源混入无关商品。 | 完整 Top-K 被直接扁平化为 `sources`。 | 区分调试用 `retrieval_sources` 与用户用 `returned_sources`。 |
| G15 | 可微波炉餐具与套装数量的结论对应商品，但用户来源混入无关商品。 | 同上。 | 同上，并拒绝无效或缺失引用。 |
| G17 | 地方特产与规格结论对应商品，但用户来源混入无关商品。 | 同上。 | 同上，并使非明确商品名的选品回答也只展示模型已验证引用。 |

## 可验证的修复假设

1. 每次请求为所有进入模型的片段稳定分配 `S1`、`S2` 等 ID，模型只能返回严格的 `answer` 与 `used_source_ids` JSON。
2. 后端仅接受属于本次上下文、无重复且格式正确的 ID；没有有效来源、引用伪造或格式无效时固定转人工，不以 Top-K 代替引用。
3. `product_id` 继续用于后端来源映射与评测断言，但不进入 prompt、最终答案或用户可见 `sources`。
4. 修复是否改善 G11、G13、G14、G15、G17，必须由下一次显式真实 LLM 运行和规定人工复核验证；不能由单元测试或本摘要代替。
