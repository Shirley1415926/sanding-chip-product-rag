# 混合检索对照实验

日期：2026-09-13
结论：**不采用 Hybrid 为默认模式，生产默认继续为 `dense`。**

## 目的与边界

本实验验证 Hybrid 是否能改善当前商城目录检索，而不是预设其一定优于 Dense。`data/test_questions.json` 的 18 道回归题和 `data/holdout_evaluation_questions.json` 的 32 道安全保留题均保持原样，未用于构造或调整本实验的压力集。

新增 `data/retrieval_stress_questions.json`，含 27 道仅可由公开资料回答的独立检索题。题目覆盖精确商品名、产地/品类、`56头`、`300g/瓶`、`80g/袋`、`10件起订`、礼盒、多条件组合和自然语言选品；每题都标明预期 `source` 与 `product_id`。它不含库存、交期、报价或未公开属性，以免把安全策略测试混入纯检索排序指标。

## 实现

- `dense`：既有 `BAAI/bge-small-zh-v1.5` + Chroma cosine Top-K。
- `bm25`：从 Chroma 当前 chunk 重建内存索引；自研确定性中文分词保留完整商品名、CJK n-gram、数字、单位与组合规格（如 `80g/袋`、`10件起订`）。BM25 原始分只用于本模式排序，再映射为 0–1 相关性置信度，以接入原有阈值门。
- `hybrid_rrf`：分别取得 Dense 和 BM25 候选排名，再按 `1 / (RRF_K + rank)` 相加。融合过程只使用名次，**不相加两种原始分数**。返回的相关性置信度取两路证据中的较高值，排名仍完全由 RRF 决定。

运行配置新增 `RETRIEVAL_MODE=dense|bm25|hybrid_rrf`、`RRF_K=60`、`RRF_CANDIDATE_DEPTH=12`；默认仍为 `dense`。`MIN_RELEVANCE` 的配置值和服务默认值都为 `0.60`，避免未显式传参时回退到旧的 `0.45`。

## 压力集结果

命令：

```bash
./.venv/bin/python scripts/run_retrieval_stress.py
```

运行使用真实本地 BGE、11 份资料生成的 33 个 chunk、`TOP_K=4`。模型构造和一次共享预热不计入延迟；延迟为这台开发机上的单次平均检索时间，仅用于同批次相对观察，不是容量基准。完整逐题排名见 `docs/HYBRID_RETRIEVAL_TRACES.json`。

| 模式 | Source Hit@1 | Hit@3 | MRR@4 | 平均检索延迟 | 串商品错误 |
| --- | ---: | ---: | ---: | ---: | ---: |
| Dense | 100.00% (27/27) | 100.00% (27/27) | 1.0000 | 6.297 ms | 0 |
| BM25 | 100.00% (27/27) | 100.00% (27/27) | 1.0000 | 0.112 ms | 0 |
| Hybrid RRF | 100.00% (27/27) | 100.00% (27/27) | 1.0000 | 5.980 ms | 0 |

Hybrid 没有提升任何检索质量指标。它与 Dense 的毫秒级单机延迟差异也不足以构成性能收益结论，因此不以该次测量宣称 Hybrid 更快。

## 安全回归检查

三个模式均重新运行冻结的 32 道安全保留集，并在 `MIN_RELEVANCE=0.60` 下得到相同结果：

| 模式 | Source Hit@1 / Hit@3（可答 17 题） | 错误回答率（32 题） | 正确转人工率（15 题） | 可答误转人工（17 题） | 串商品错误 |
| --- | --- | --- | --- | --- | ---: |
| Dense | 17/17 · 17/17 | 0/32 | 15/15 | 0/17 | 0 |
| BM25 | 17/17 · 17/17 | 0/32 | 15/15 | 0/17 | 0 |
| Hybrid RRF | 17/17 · 17/17 | 0/32 | 15/15 | 0/17 | 0 |

自动化测试还断言三个检索模式接入同一个硬安全门：库存类问题不会调用检索；0.59 的证据在 0.60 阈值下统一转人工；`Settings`、服务默认值和运行时默认模式分别固定为 0.60、0.60、Dense。

## 失败案例与限制

本次压力集没有出现检索错源或串商品失败；这不是 Hybrid 已被证明无价值，而是小型、结构化目录中的三个方案均已达到上限。当前不能从 27 题得出 Hybrid 对更多商品、别名、错别字、跨语言表述或长文档也无收益的结论。

已观察到的风险和下一步验证重点：

1. BM25 的 CJK n-gram 会在目录扩大后带来更多宽泛词重叠；需要以新增资料和真实查询复测，不能把当前 100% 外推。
2. Hybrid 的阈值置信度用于保持既有安全门行为，不是 RRF 分数的通用校准；语料、模型或检索深度变更后必须重新跑安全保留集。
3. 当前压力集只测公开可回答商品题；仍需在未来独立集加入别名、错别字和更接近线上表达的歧义问题，且不能改写现有冻结集。

因此，保留三种可配置模式用于后续复验，但不更改默认值，也不引入 Rerank、MCP、Dashboard 或网页聊天界面。
